# Authoring Workflow

## 1. Start from a production need

Describe the recurring behaviour that project-specific prompting does not capture reliably.

## 2. Check the catalogue

Reuse or refine an existing pack when it already covers the medium and production language. Do not create synonyms.

## 3. Define the production profile

Separate:

```text
hard constraints
soft defaults
intentional traits
quality requirements
handoff requirements
```

## 4. Define core-skill effects

Only add guidance to core skills that actually need it. A prose pack may not need continuity changes; an interactive narrative pack often does.

## 5. Define evaluation before examples

State what the evaluator should preserve, what it should not penalise, and what still counts as failure.

## 6. Add voice casting only when useful

Use role/performance direction by default. Add provider voice references only when they are stable, licensed/configured, and materially useful.

## 7. Package locally

Keep runtime resources under the pack's skill directory. Do not depend on repository-level docs.

## 8. Create the showcase

The example README must contain the exact prompt that activates the pack and exposes its characteristic behaviour.

## 9. Add behavioural evals

Cover normal use, draft/exploration, refinement, final/readiness, and boundary/precedence behaviour.
